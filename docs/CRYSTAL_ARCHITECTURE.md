# UNIBUD Crystal Architecture Register

Status: canonical consolidation record, 2026-09-30.

This register preserves architectural "crystals": stable intelligence/system principles and structural components that must survive repository consolidation. A crystal is not automatically a user-facing agent. It is a durable architectural unit, relationship, boundary, or principle.

## Core intelligence crystal

Oracle
- Knowledge & Intelligence Core.
- Strategic verification, knowledge coordination, conflict resolution and system-level intelligence.
- Oracle is not replaced by Bud, Spark, Fixer, or another renamed role.

Bud
- The only user-facing conversational AI.
- Shared across UNIBUD contexts.
- Owns the visible conversation and expression.

Spark
- Hidden orchestration layer.
- Receive → Understand → Classify → Determine Required Intelligence → Route → Coordinate → Verify → Resolve → Execute → Review → Return.
- Coordinates only the intelligence actually required.

## Context crystals

UNIBUD is one application/world with multiple contexts.

Social context:
Square → social content, Stories, Watch, Podcasts, Live, campus/school updates, Events, Discovery.

Academic context:
Campus/Board/Academy → courses, syllabus, classes, assignments, exams, results, research and teaching.

Discovery context:
Quad → opportunities, discovery and current activity.

Communication context:
Connect + Chat → people, connections, direct conversations and groups.

Services context:
Campus utilities and platform services.

The same Bud remains available across contexts; the context changes what intelligence is required.

## Reality crystal

The system must never manufacture:
- activity
- memories
- trends
- agent actions
- provider connections
- money
- catalogue items
- external results

A missing provider/capability must produce an honest unavailable state.

## Agent crystal

The 52-role catalog is the current consolidated intelligence inventory. The 52 roles must be treated as one coordinated intelligence system, not 52 independent chatbots.

The existing 15-agent runtime spine remains the execution foundation. Additional roles are domain/service capabilities and should become executable only when their real implementation/capability exists.

## Known failure crystals to prevent recurrence

- PGlite leaking into Netlify production runtime.
- Better Auth attempting to use unavailable local database paths in production.
- In-memory/mock data presented as real data.
- Fake activity used to make the world appear alive.
- External provider behavior simulated when the provider is disconnected.
- Multiple repositories treated as competing sources of truth.
- Old navigation/design generations revived accidentally.
- Agents treated as theatrical personalities instead of real system roles.
- Architecture renamed or simplified without explicit approval.

## Preservation rule

When consolidating repositories, preserve the strongest verified implementation, then recover missing architectural crystals from the older repositories. Do not copy obsolete infrastructure merely because it contains more files.

## Unresolved crystal naming

A repository-wide search for the literal word "crystal" did not find a formal crystal registry. Therefore this file records the architectural units we can verify from the existing code and architecture documents, but it does not invent names for crystals that have not yet been recovered.

Any previously named crystal not present in this register remains an unresolved historical item and must be added when its exact definition is recovered.
